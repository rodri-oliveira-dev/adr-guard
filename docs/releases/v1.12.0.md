# ADR Guard CLI v1.12.0

[Português (Brasil)](v1.12.0.pt-BR.md)

<!-- release-candidate-only:start -->
ADR Guard CLI `1.12.0` is prepared in source control but is **not yet published**. CLI `1.11.0` remains the current public CLI, container, and GitHub Action release. MCP `1.0.1` and VS Code `1.1.1` are published independently. Do not use this page as evidence that a package, image, Action tag, Marketplace listing, or GitHub Release has been updated.
<!-- release-candidate-only:end -->

## Highlights

- Adds the read-only `adr-guard relationships [directory] --format json` command for deterministic navigation of declared ADR relationships.
- Emits the strict relationship graph schema `1.0`: ADR nodes, explicit `depends-on`, `supersedes`, and `superseded-by` edges, declared targets, resolution states, matching candidates, and existing relationship diagnostics.
- Centralizes relationship discovery in the internal `AdrGuard.Core` assembly so validation, CLI export, and MCP reuse one deterministic implementation.
- Never infers relationships from narrative text, semantics, or AI output and never creates, edits, approves, replaces, or changes the status of an ADR.

## Compatibility and limits

- Existing `check` JSON and SARIF contracts remain unchanged; the relationship graph is an additive schema `1.0` contract.
- Existing commands, arguments, deterministic ordering, fingerprints, and exit codes `0`–`4` remain compatible.
- The command accepts the established ADR format, validation profile, lifecycle, filename, and conventional-supersession settings and applies the same strict configuration rules as validation.
- Input enumeration, file sizes, paths, nodes, relationships, and serialized output remain bounded. Missing, ambiguous, outside-workspace, or unverifiable targets are represented explicitly rather than guessed.
- `AdrGuard.Core` remains internal and non-packable with no independent version.

## Distribution

<!-- release-candidate-only:start -->
After merge and successful CI for the selected `main` commit, an authorized maintainer may manually dispatch **Release** with `version=1.12.0`. The workflow validates, builds, tests, packs, installs, and smoke-tests the selected commit before it can publish anything.
<!-- release-candidate-only:end -->

The coordinated **Release** workflow can:

- publish `RodriOliveira.AdrGuard` `1.12.0` to NuGet.org and GitHub Packages;
- publish matching `linux/amd64` and `linux/arm64` images to GHCR and Docker Hub;
- create the immutable `v1.12.0` tag, move the compatible `v1` Action tag only after runtime publication succeeds, and create the matching GitHub Release from these curated notes.

Merging this preparation does not publish packages, images, tags, or releases. The GitHub Action continues to expose only its existing `check`, `index`, `review`, `impact`, and `drift` operations; `relationships` is a direct CLI contract used by compatible visual clients.

## Independent components

- VS Code `1.2.0` is prepared separately and requires a CLI whose `relationships --help` exposes this contract. It detects an older or malformed CLI and shows an explicit incompatible state.
- MCP `1.0.2` is prepared separately because its existing `get_adr_relationships` tool now uses the shared Core implementation. Its seven tools, schema `1.0`, transport, and read-only boundaries remain unchanged.
