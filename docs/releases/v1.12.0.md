## Highlights

- Adds `adr-guard export relationships [directory]` for deterministic JSON export of ADR metadata, declared relationships, and attributable validation diagnostics.
- Defines the portable ADR relationships export contract with `"schemaVersion": "1.0"` and byte-canonical examples for external consumers, including Align.
- Distinguishes target identity resolution (`resolved`, `ambiguous`, or `unresolved`) from relationship semantics. A resolved target is not evidence that the relationship is valid, approved, or compliant.

## Command and output

```bash
adr-guard export relationships docs/adr
adr-guard export relationships docs/adr --output artifacts/relationships.json
```

The default output is `.adr-guard/relationships.json`. An explicit `--output` must be a portable JSON path within the repository. The artifact contains three deterministically ordered arrays:

- `adrs`: identifier, repository-relative path, title, and validated status;
- `relationships`: every declared `supersedes`, `superseded-by`, and `depends-on` edge, including source, declaration, resolved target when available, and resolution classification;
- `issues`: attributable Core diagnostics with code, severity, message, and repository-relative path.

The export has no timestamps or implicit Git state. Identical repository contents and explicit inputs produce identical bytes.

## Exit behavior

- `0`: the artifact was written, including when `issues` is non-empty;
- `2`: command usage or repository configuration is invalid;
- `3`: input loading, path/security validation, cancellation, or output I/O failed.

Export is an integration operation, not a policy gate. Run `adr-guard check` separately when validation findings must control CI; the established CLI exit meanings `1` for findings and `4` for deterministic policy failure remain unchanged for commands that use them.

## Security, portability, and reliability

- Inputs are valid UTF-8 Markdown, limited to 1,000 ADRs and 524,288 bytes per ADR.
- Discovery skips symlinks and reparse points. Repository containment rejects absolute paths, traversal, symlink escapes, and paths that cannot be represented by the portable `/`-separated contract.
- The writer creates and flushes a temporary file in the destination directory before replacing the prior artifact. It does not edit ADRs, indexes, configuration, or Git state.
- Export requires no network, model, provider, or credential. Consumers such as Align can ingest the completed JSON without running ADR Guard, .NET, MCP, or an AI integration.
- AI output and a resolved edge remain advisory data; neither can approve an ADR or establish compliance.

## Compatibility and known limitations

- Schema `1.0` is additive to existing CLI contracts. Its `major.minor` compatibility policy requires a new major version for incompatible changes; no existing JSON or SARIF schema was changed.
- Existing commands, arguments, validation fingerprints, ordering, and exit-code contracts are preserved.
- The export reports declared relationships and attributable validation diagnostics. It does not infer undeclared edges, evaluate architectural merit, enforce findings, or inspect external repositories.
- `resolution: "resolved"` means exactly one target identity was found. Cycles, inconsistent inverse declarations, inactive dependencies, invalid statuses, and other semantic findings remain in `issues`.
- The current MCP source reuses the Core producer but maps results to the existing MCP schema `1.0` contract and historical `valid` resolution value. MCP `1.0.1` is not republished or versioned by this CLI release.

The coordinated **Release** workflow validates stable SemVer against `VersionPrefix`, restores, builds, tests, packs, installs, and smoke-tests the selected CLI commit before it can:

- create exact tag `v1.12.0`, move compatibility tag `v1` only after publication gates pass, and create the GitHub Release from these curated notes.

Merging this preparation does not publish artifacts, create tags, move `v1`, or create a release.

## Components outside this release

- `AdrGuard.Core` is internal and non-packable; it ships inside the CLI package and has no independent version.
- MCP remains independently versioned at published `1.0.1`, with its own workflow. Its package version and Registry manifest are unchanged.
- VS Code remains independently versioned at source candidate `1.1.1`; it is not bundled or published by the CLI workflow.
- `AdrGuard.Agent` remains unversioned, development-only source. It has no package, installer, container, manifest, or release channel and is not part of the CLI `1.12.0` distribution.
