# ADR Guard v1.1.0 — Offline ADR creation and template-aware AI drafts

This release adds deterministic offline ADR creation with built-in Minimal, Extended and explicit custom Markdown templates, plus optional template selection for the existing AI-assisted `draft`.

## Create an ADR without AI

```bash
mkdir -p docs/adr
adr-guard new docs/adr --title "Adopt Redis"
adr-guard new docs/adr --title "Adopt Kafka" --template extended --culture pt-BR
adr-guard new docs/adr --title "Adopt Cache" --template-file docs/examples/templates/team.en-US.md
adr-guard new docs/adr --title "Preview only" --dry-run
adr-guard check docs/adr
adr-guard index docs/adr
```

`new` does not require a provider, API key or network access, and does not update the index automatically. `--preview` and `--dry-run` validate and display the prospective filename and Markdown without writing or reserving an ID. Templates support `en-US` and `pt-BR` guidance; canonical `Status`, `Context`, `Decision`, `Consequences` headings and initial `Proposed` status remain English. Custom template files are explicitly selected UTF-8 Markdown up to 65,536 bytes, with strict single-pass placeholders. Concurrent cooperative creators on the same host share ID allocation and atomic no-overwrite persistence; `{{id}}` is re-rendered with the final allocated ID.

## Optional templates for AI-assisted `draft`

```bash
adr-guard draft docs/adr --title "Adopt Redis" \
  --context "We need bounded caching." \
  --provider openai --model YOUR_MODEL --template extended --preview
```

Use `--template minimal|extended` or `--template-file <path>` to select local rendering after the configured provider returns. **Template source, guidance and path are not sent to the provider.** Architectural context is sent only from `--context`, explicitly selected `--context-file` inputs, and parsed existing ADRs only with `--include-existing-adrs`. Unlike offline preview, `draft --preview` calls the provider but skips persistence. Without template flags, `draft` retains its previous output, provider contract and culture behavior. Generated ADRs remain **Proposed** and require human review; structural validity is not architectural approval.

## Compatibility and distribution

`check`, `index`, the default `draft`, exit codes 0–3 and diagnostics ADR001–ADR009 retain their contracts. The public GitHub Action `rodri-oliveira-dev/adr-guard@v1` continues to support **only `check` and `index`**: use the .NET Tool or separately invoked container for `new` and `draft`. Native MADR/alternate-format validation is not introduced.

After the release publishes, update the .NET Tool with `dotnet tool update --global RodriOliveira.AdrGuard --version 1.1.0` or pin the image to `ghcr.io/rodri-oliveira-dev/adr-guard:1.1.0` / `docker.io/rodrigodotnet/adr-guard:1.1.0`. NuGet.org, GitHub Packages, GHCR, Docker Hub and immutable `v1.1.0`/moving `v1` are verified by the release workflow **after owner-approved merge**. This note is prepared before public publication.
