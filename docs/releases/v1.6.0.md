# ADR Guard v1.6.0 release candidate

ADR Guard 1.6.0 is the proposed next backward-compatible feature release after the verified public v1.5.0 distribution. This pull request does not publish, tag, merge, move Action references, or upload artifacts.

## Architectural drift

- Adds `adr-guard drift` with stable text/JSON reports, advisory default policy and explicit deterministic enforcement.
- Links versioned fitness rules to effective ADR identity/lifecycle semantics from earlier releases.
- Proves exact static forbidden `.csproj` references without invoking MSBuild; conditional, dynamic and unsafe inputs remain `unknown`.
- Imports optional local external-test JSON as reported, unattested evidence with producer/run/artifact provenance.
- Adds stable semantic fingerprints and explicit atomic snapshot/baseline creation and update.

## Security and compatibility

The implementation rejects DTD/entities, unsafe paths, symlink traversal, duplicate/unknown JSON fields and excessive input. It performs no network discovery or arbitrary execution. External results and AI output never become automatic CI proof. Existing commands, Action inputs, extension integration, check JSON/SARIF, review and impact contracts are unchanged.

## Distribution impact and release gate

The .NET Tool payload changes, so NuGet, GitHub Packages and the containers that carry the CLI require coordinated v1.6.0 publication. The composite Action itself has no new input or behavior and the VS Code extension is unchanged; their existing compatibility contracts must still pass. The protected release workflow may run only after this PR is approved and merged, CI succeeds on the exact `main` commit, and a maintainer explicitly dispatches version `1.6.0`.

## Install after publication

```bash
dotnet tool install --global RodriOliveira.AdrGuard --version 1.6.0
```
