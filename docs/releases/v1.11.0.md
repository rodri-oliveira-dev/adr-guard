# ADR Guard CLI v1.11.0

MCP `1.0.1` and VS Code `1.1.1` are separate unpublished candidates. Do not use this page as evidence that any registry, Action tag, Marketplace listing, or GitHub Release has been updated.

## Highlights

- Adds native MADR 4.0 generation to `adr-guard new` with built-in `minimal` and `extended` templates.
- Selects MADR explicitly with `--adr-format madr-4` or through repository `adr-format`, while an explicit option retains precedence and canonical generation remains the default.
- Supports exact, side-effect-free `--preview` and `--dry-run` output and the schema `1.0` `new --form` operations `describe`, `preview`, and `create`.
- Preserves atomic writes, safe concurrent ID allocation, filename policies, bounded inputs, and the rule that generated documents are only human-reviewable `proposed` drafts.

## Compatibility

- Existing canonical templates and their generated bytes remain unchanged. Custom templates remain canonical-only.
- The `new --form` JSON envelope stays at schema `1.0`. MADR reuses published field IDs instead of adding fields that strict existing clients could reject.
- Existing CLI arguments, exit codes `0`–`4`, validation schemas, deterministic ordering, and human-owned ADR approval remain compatible.
- MADR format selection applies to the complete validation or generation operation; canonical and MADR records should remain in separately invoked directories.
- The runtime remains .NET 10. Native MADR generation is offline and requires neither MCP nor an AI provider.

## Distribution prepared by this release

After merge and a successful CI run for the selected `main` commit, an authorized maintainer may manually dispatch **Release** with `version=1.11.0`. The workflow validates, builds, tests, packs, installs, and smoke-tests the release build before it can:

- publish `RodriOliveira.AdrGuard` `1.11.0` to NuGet.org and GitHub Packages;
- publish the same CLI build for `linux/amd64` and `linux/arm64` to GHCR and Docker Hub;
- create the exact `v1.11.0` tag, move the `v1` compatibility tag only after publication gates pass, and create the matching GitHub Release.

No publication, tag creation, or tag movement occurs merely by merging this preparation.

## Security and reliability

- Preview and dry-run create no ADR, index, temporary artifact, lock file, or ID reservation.
- Creation renders again under the existing cross-process allocation lock, validates the final content, and atomically promotes a temporary file without overwriting an existing ADR.
- Custom templates cannot inject a MADR structure, and format/configuration inputs retain strict parsing and repository-bound path handling.
- Generated `status: "proposed"` metadata is advisory drafting state and never implies architectural approval or compliance.

## Related independent components

- `AdrGuard.Core` remains internal and non-packable; it has no independent version or release.
- MCP remains at source candidate `1.0.1`, with separately published `1.0.0` artifacts and its independent **MCP Release** workflow.
- VS Code remains at source candidate `1.1.1`; it invokes a separately installed compatible CLI and is not bundled with this package.
