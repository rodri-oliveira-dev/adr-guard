# ADR Guard CLI v1.9.0

[Português (Brasil)](v1.9.0.pt-BR.md)

<!-- release-candidate-only:start -->
ADR Guard CLI `1.9.0` is prepared in source control but, as of 2026-10-20, is **not published** on NuGet.org, GitHub Releases, the container registries, or the GitHub Action tag. The current public CLI remains `1.8.0`. This is a backward-compatible minor candidate because it adds an opt-in diagnostic capability without changing existing defaults or contracts.
<!-- release-candidate-only:end -->

## Highlights

- Adds `check --diagnostic-locations` so JSON and SARIF reports can include evidenced, one-based line and column locations. Without the flag, the existing report shape is unchanged.
- Preserves parser-backed locations for relationship findings, including an existing but empty or unusable `Superseded by` section.
- Uses the internal `AdrGuard.Core` assembly for shared parsing, validation, configuration, Git inventory, impact, and drift behavior. Core is shipped inside the CLI package and is not a public NuGet library or independent release.
- Improves physical Git-directory resolution on macOS path aliases and expands cross-platform CLI reliability coverage.

## Fixes and internal improvements

- Keeps findings without reliable source evidence at file scope instead of inventing coordinates.
- Adds deterministic CLI smoke coverage for `init`, `new`, `check`, `index`, incremental validation, JSON schema `1.0`, and exits `0`/`1` on Linux, Windows, and macOS CI.
- Adds an informational, reproducible performance baseline. It is not an SLA or release gate.
- Packages `AdrGuard.Core.dll` with the CLI while excluding the MCP executable.

## Compatibility and requirements

- Requires .NET 10.
- Preserves all existing commands, arguments, defaults, exit codes (`0`–`4`), JSON schema `1.0`, SARIF `2.1.0`, diagnostic identities/fingerprints, form contracts, and deterministic ordering.
- The published VS Code extension `1.1.0` can use this CLI when installed separately. Its Problems integration requests precise locations and retains its fallback for older CLI versions.
- MCP is versioned and installed independently. MCP `1.0.1` preserves a separate release stream; neither executable depends on the other.

## Behavior changes

The only new public CLI behavior is opt-in. When `--diagnostic-locations` is present with JSON or SARIF output, findings include line/column data only where the parser retained concrete evidence. Omitting the flag preserves the previous machine-readable shape. No validation rule, severity, default, command, or exit-code meaning changes.

## Known limitations

- Some repository-wide, front-matter, or missing-section findings have no provable coordinates and remain file-only.
- The performance measurements are environment-specific and informational.
- AI drafting and review remain optional, bounded, and advisory. Neither AI nor MCP can approve an ADR or establish compliance.

## Install or update

<!-- release-candidate-only:start -->
Before publication, install only the locally validated package produced from this commit:

```shell
dotnet tool install --tool-path ./.tools RodriOliveira.AdrGuard \
  --version 1.9.0 --add-source ./artifacts/packages
./.tools/adr-guard --version
```

Do not use the public NuGet commands for `1.9.0` until NuGet.org lists that exact version. The manual release workflow remains the only supported publication path.
<!-- release-candidate-only:end -->

When NuGet.org lists the exact version, install it with:

```shell
dotnet tool install --global RodriOliveira.AdrGuard --version 1.9.0
adr-guard --version
```
