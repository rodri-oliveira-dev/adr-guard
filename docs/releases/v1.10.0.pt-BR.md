# ADR Guard CLI v1.10.0

[English](v1.10.0.md)

<!-- release-candidate-only:start -->
A CLI ADR Guard `1.10.0` está preparada no código-fonte, mas **ainda não foi publicada**. A release pública atual da CLI, dos containers e da GitHub Action continua sendo `1.9.0`. VS Code `1.1.1` e MCP `1.0.1` também são candidatas independentes ainda não publicadas. Esta página não comprova atualização em qualquer registry, tag da Action, listagem do Marketplace ou GitHub Release.
<!-- release-candidate-only:end -->

## Principais mudanças

- Adiciona `adr-guard doctor [repositório]`, comando local somente leitura que diagnostica identidade da CLI, detecção do repositório, configuração estrita, diretório efetivo de ADRs, runtime .NET e disponibilidade opcional do Git.
- Integra à GitHub Action a verificação explícita e somente leitura de `drift`, com regras, política advisory/enforce, baseline existente opcional e evidências externas limitadas.
- Melhora onboarding e diagnóstico para desenvolvimento sem enfraquecer a validação determinística nem retirar das pessoas a responsabilidade pelo status e aprovação das ADRs.
- Reúne a manutenção e o reforço de segurança das Fases 1 e 2, as reduções de complexidade cognitiva concluídas no PR #300 e cobertura adicional de confiabilidade e regressão.

## Compatibilidade

- `doctor` é aditivo. Comandos, argumentos, padrões, códigos de saída `0`–`4`, schema JSON `1.0`, SARIF `2.1.0`, fingerprints e ordenação determinística existentes permanecem compatíveis.
- O modo `drift` da Action delega política e achados ao container da CLI. O adaptador valida caminhos e entradas e produz resumo limitado; ele não implementa um segundo motor de regras.
- A CLI continua referenciando `AdrGuard.Core`, interno e não empacotável. O MCP referencia diretamente o mesmo projeto Core e permanece independente do executável da CLI.
- A extensão VS Code instalada separadamente executa a CLI externamente. VS Code `1.1.1` e MCP `1.0.1` permanecem versionados separadamente e não acompanham este pacote.
- O runtime continua sendo .NET 10. Git é opcional, salvo nos comandos que exigem evidência Git local; providers de IA configurados continuam opcionais em `draft` e `review`.

## Distribuição preparada por esta release

Depois do merge e de uma execução de CI bem-sucedida para o commit selecionado da `main`, uma pessoa mantenedora autorizada poderá disparar manualmente **Release** com `version=1.10.0`. O workflow valida, compila, testa, empacota e instala o build de release de forma isolada antes de poder:

- publicar `RodriOliveira.AdrGuard` `1.10.0` no NuGet.org e no GitHub Packages;
- publicar o mesmo build da CLI para `linux/amd64` e `linux/arm64` no GHCR e no Docker Hub;
- criar ou conferir a tag exata `v1.10.0`, mover a tag de compatibilidade `v1` somente depois dos gates de publicação e criar a GitHub Release correspondente;
- disponibilizar o modo `drift` da Action nas tags exata e móvel, com a imagem de runtime resolvida para `1.10.0`.

O merge desta preparação, isoladamente, não publica artefatos nem cria ou move tags.

## Segurança e confiabilidade

- As imagens de build/runtime usam variantes Alpine oficiais do .NET, preservam o Git limitado e executam com usuário não root.
- A publicação mantém actions fixadas, permissões mínimas por job, checks de CI/proveniência, instalação isolada dos pacotes, varredura de vulnerabilidades, verificação de manifests multiplataforma, SBOM e attestations de proveniência.
- Evidência de drift ausente, inválida, incompatível ou fora do escopo continua sendo `unknown`/inconclusiva, nunca conformidade inferida.

## Componentes independentes relacionados

- MCP `1.0.1`: sete tools somente leitura no schema `1.0` por `stdio`, referência direta ao Core e nenhuma dependência do executável da CLI. O `.mcp/server.json` versionado permanece intencionalmente em `1.0.0`; o workflow **MCP Release** gera o manifesto da versão solicitada durante a execução.
- VS Code `1.1.1`: patch de manutenção para VS Code `1.101.0+`; o VSIX não inclui CLI nem MCP. O workflow do repositório gera somente um artifact validado, e a publicação no Marketplace continua sendo uma ação manual separada da pessoa proprietária.
