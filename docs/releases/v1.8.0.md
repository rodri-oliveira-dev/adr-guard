# ADR Guard v1.8.0

[Português (Brasil)](v1.8.0.pt-BR.md)

ADR Guard CLI 1.8.0 was published as a [GitHub Release](https://github.com/rodri-oliveira-dev/adr-guard/releases/tag/v1.8.0) on 2026-10-17, with `RodriOliveira.AdrGuard.1.8.0.nupkg` attached. It provides compatible CLI/domain contracts for independently versioned VS Code 1.1.0 and MCP 1.0.0 source candidates. This CLI release does **not** establish the publication of those separate components, or independently confirm NuGet.org, container, or Action-tag availability.

## Included

- Preserves all established CLI commands and contracts: `init`, `check`, `baseline`, `index`, `new`, `edit`, `draft`, `review`, `impact`, and `drift`.
- Preserves canonical validation defaults, opt-in MADR 4.0, lifecycle/relationship policies, diagnostic baselines, incremental validation, text/JSON/SARIF reports, enriched catalogs, impact analysis, drift verification, and human-reviewed AI workflows.
- Exposes the existing domain services to the separately packaged read-only MCP adapter without moving policy or validation logic out of the CLI assembly.
- Closes Git subprocess standard input so a child Git process cannot consume MCP protocol input during impact or drift analysis.
- Adds audited bilingual documentation and compatibility guidance for CLI 1.8.0, VS Code 1.1.0, and MCP 1.0.0.

No CLI command, flag, report schema, default, or exit-code meaning is intentionally changed in this release. AI drafting/review and MCP results remain advisory; humans own ADR status and approval.

## Install CLI 1.8.0

```shell
dotnet tool install --global RodriOliveira.AdrGuard --version 1.8.0
adr-guard --version
```

For an existing global installation, use `dotnet tool update --global RodriOliveira.AdrGuard --version 1.8.0`. These installation commands retrieve from NuGet.org: confirm that exact version is available there before relying on them. The [published GitHub Release](https://github.com/rodri-oliveira-dev/adr-guard/releases/tag/v1.8.0) separately provides the `.nupkg` asset. Publishing future CLI versions remains a protected, manual process.

## Compatibility

- Runtime: .NET 10.
- VS Code 1.1.0 requires a separately installed compatible CLI; CLI 1.8.0 is the recommended version for every visual architecture, governance, and AI workflow. Visual create/edit contracts remain schema `1.0` and compatible with CLI 1.7.0 or newer.
- MCP 1.0.0 is independently installed and does not require the extension. The CLI does not require either MCP or VS Code.

See the [compatibility matrix](../compatibility.md), [CLI reference](../cli-reference.md), and [release process](../github-action-release.md).
