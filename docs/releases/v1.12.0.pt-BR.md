# ADR Guard CLI v1.12.0

[English](v1.12.0.md)

<!-- release-candidate-only:start -->
A CLI ADR Guard `1.12.0` está preparada no código-fonte, mas **ainda não foi publicada**. A CLI `1.11.0` continua sendo a release pública atual da CLI, dos containers e da GitHub Action. MCP `1.0.1` e VS Code `1.1.1` estão publicados de forma independente. Não use esta página como evidência de atualização de pacote, imagem, tag da Action, listagem do Marketplace ou GitHub Release.
<!-- release-candidate-only:end -->

## Destaques

- Adiciona o comando somente leitura `adr-guard relationships [diretório] --format json` para navegação determinística dos relacionamentos declarados entre ADRs.
- Emite o schema estrito `1.0` do grafo: nós de ADR, arestas explícitas `depends-on`, `supersedes` e `superseded-by`, alvos declarados, estados de resolução, candidatos correspondentes e diagnósticos de relacionamento existentes.
- Centraliza a descoberta de relacionamentos no assembly interno `AdrGuard.Core`, permitindo que validação, exportação pela CLI e MCP reutilizem uma única implementação determinística.
- Nunca infere relacionamentos a partir de narrativa, semântica ou saída de IA e nunca cria, edita, aprova, substitui ou altera o status de uma ADR.

## Compatibilidade e limites

- Os contratos JSON e SARIF existentes do `check` permanecem inalterados; o grafo é um contrato aditivo no schema `1.0`.
- Comandos, argumentos, ordenação determinística, fingerprints e códigos de saída `0`–`4` existentes permanecem compatíveis.
- O comando aceita as configurações existentes de formato, perfil de validação, ciclo de vida, nomes e supersessão convencional, aplicando as mesmas regras estritas da validação.
- Enumeração de entrada, tamanhos de arquivo, caminhos, nós, relacionamentos e saída serializada continuam limitados. Alvos ausentes, ambíguos, fora do workspace ou não verificáveis são representados explicitamente, nunca adivinhados.
- `AdrGuard.Core` permanece interno, sem pacote ou versão independente.

## Distribuição

<!-- release-candidate-only:start -->
Depois do merge e de CI bem-sucedido para o commit selecionado da `main`, uma pessoa mantenedora autorizada pode disparar manualmente **Release** com `version=1.12.0`. O workflow valida, compila, testa, empacota, instala e executa smoke tests no commit selecionado antes de publicar qualquer item.
<!-- release-candidate-only:end -->

O workflow coordenado **Release** pode:

- publicar `RodriOliveira.AdrGuard` `1.12.0` no NuGet.org e GitHub Packages;
- publicar imagens correspondentes para `linux/amd64` e `linux/arm64` no GHCR e Docker Hub;
- criar a tag imutável `v1.12.0`, mover a tag compatível `v1` da Action somente depois da publicação bem-sucedida do runtime e criar a GitHub Release correspondente com estas notas curadas.

O merge desta preparação não publica pacotes, imagens, tags ou releases. A GitHub Action continua expondo somente as operações existentes `check`, `index`, `review`, `impact` e `drift`; `relationships` é um contrato direto da CLI usado por clientes visuais compatíveis.

## Componentes independentes

- VS Code `1.2.0` é preparado separadamente e exige uma CLI cujo `relationships --help` exponha este contrato. Ele detecta uma CLI antiga ou malformada e apresenta um estado incompatível explícito.
- MCP `1.0.2` é preparado separadamente porque sua ferramenta existente `get_adr_relationships` agora usa a implementação compartilhada do Core. As sete ferramentas, schema `1.0`, transporte e limites somente leitura permanecem inalterados.
