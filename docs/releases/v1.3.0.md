# ADR Guard v1.3.0

Version 1.3.0 consolidates the capabilities originally prepared in the v1.3 and v1.4 development branches into **one coordinated release**. This is a release-note draft, not evidence that any package has already been published.

## Validation formats and architecture governance

- Add explicit, opt-in MADR 4.0 validation using official full and minimal templates. Select it with `--adr-format madr-4` or the matching configuration; canonical ADR Guard remains the default.
- Add deterministic cross-ADR relationship governance with diagnostics `ADR010`–`ADR014`, preserving the existing `ADR001`–`ADR009` codes.
- Extend text, JSON (schema 1.0), SARIF, and associated reporting to expose the applicable diagnostic codes.

## Git-aware validation and baselines

- Support **opt-in incremental Git validation** of changed ADRs via `check --changed --base-ref <ref>`, while retaining global integrity validation. No hidden fetch occurs.
- Add strictly validated, versioned diagnostic baselines and explicit atomic baseline create/update commands.
- Report new, existing, and resolved diagnostics consistently. Compute baseline resolutions against the full current set of ADRs before filtering new/existing diagnostics for changed-file mode.
- Validate Git base references and deduplicate diagnostic fingerprints before storing baselines.

## Comparative architectural review

- Add explicit AI-assisted comparison of two versions of the same ADR, with bounded historical context and existing provider, security, and human-review requirements preserved.
- Add deterministic Git-backed, mocked-provider, cancellation, security, and regression tests and bilingual documentation.

## Compatibility and release process

- Existing canonical ADR repositories require **no migration**. MADR, incremental validation, baselines, and comparative review are explicit/opt-in capabilities.
- Features previously described as planned for `v1.4.0` are **included in v1.3.0**. They are not postponed to a separate feature release.
- The package ID remains `RodriOliveira.AdrGuard` and the .NET Tool command remains `adr-guard`.
- Publication remains **manual**: the existing coordinated `Release` workflow accepts exact version `1.3.0` after a successful CI run on the chosen `main` SHA, and publishes NuGet.org, GitHub Packages, container images, GitHub Action tags, and a GitHub Release. Merging the PR does not start publication.

After publication, install exactly this version with:

```bash
dotnet tool install --global RodriOliveira.AdrGuard --version 1.3.0
```
