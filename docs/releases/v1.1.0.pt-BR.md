# ADR Guard v1.1.0 — Criação offline de ADRs e templates no draft com IA

Esta release acrescenta criação offline determinística de ADRs com templates Minimal, Extended e Markdown personalizado explicitamente selecionado, além da seleção opcional de templates no `draft` assistido por IA existente.

## Crie uma ADR sem IA

```bash
mkdir -p docs/adr
adr-guard new docs/adr --title "Adotar Redis" --culture pt-BR
adr-guard new docs/adr --title "Adotar Kafka" --template extended --culture pt-BR
adr-guard new docs/adr --title "Adotar Cache" --template-file docs/examples/templates/team.pt-BR.md --culture pt-BR
adr-guard new docs/adr --title "Somente prévia" --dry-run
adr-guard check docs/adr
adr-guard index docs/adr
```

`new` não exige provedor, chave de API nem rede e não atualiza o índice automaticamente. `--preview` e `--dry-run` validam e exibem o caminho e o Markdown prováveis sem gravar ou reservar ID. As instruções são localizadas para `en-US` e `pt-BR`; os títulos canônicos `Status`, `Context`, `Decision`, `Consequences` e o status inicial `Proposed` permanecem em inglês. Arquivos de template personalizado são Markdown UTF-8 selecionados explicitamente, limitados a 65.536 bytes e placeholders estritos de passagem única. Criadores cooperantes no mesmo host compartilham alocação de IDs e persistência atômica sem sobrescrita; `{{id}}` é renderizado novamente com o ID final.

## Templates opcionais para `draft` com IA

```bash
adr-guard draft docs/adr --title "Adotar Redis" \
  --context "Precisamos de cache limitado." \
  --provider openai --model SEU_MODELO --template extended --culture pt-BR --preview
```

Use `--template minimal|extended` ou `--template-file <caminho>` para selecionar a renderização local após a resposta do provedor configurado. **O arquivo, as instruções e o caminho do template não são enviados ao provedor.** O contexto arquitetural enviado vem exclusivamente de `--context`, arquivos `--context-file` selecionados explicitamente e ADRs existentes interpretadas somente com `--include-existing-adrs`. Diferentemente da prévia offline, `draft --preview` chama o provedor, mas não grava. Sem flags de template, `draft` mantém a saída, o contrato do provedor e as culturas anteriores. As ADRs geradas permanecem **Proposed** e exigem revisão humana; validade estrutural não é aprovação arquitetural.

## Compatibilidade e distribuição

`check`, `index`, `draft` padrão, códigos de saída 0–3 e diagnósticos ADR001–ADR009 mantêm seus contratos. A GitHub Action pública `rodri-oliveira-dev/adr-guard@v1` continua aceitando **somente `check` e `index`**: use a .NET Tool ou container separado para `new` e `draft`. Não foi adicionada validação nativa de MADR/formatos alternativos.

Após a publicação, atualize com `dotnet tool update --global RodriOliveira.AdrGuard --version 1.1.0` ou fixe a imagem em `ghcr.io/rodri-oliveira-dev/adr-guard:1.1.0` / `docker.io/rodrigodotnet/adr-guard:1.1.0`. NuGet.org, GitHub Packages, GHCR, Docker Hub e tags imutáveis `v1.1.0` / móvel `v1` são verificados pelo workflow **após o merge autorizado pelo proprietário**. Estas notas foram preparadas antes da publicação pública.
