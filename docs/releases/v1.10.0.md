# ADR Guard CLI v1.10.0

[Português (Brasil)](v1.10.0.pt-BR.md)

<!-- release-candidate-only:start -->
ADR Guard CLI `1.10.0` is prepared in source control but is **not yet published**. The current public CLI, container, and GitHub Action release remains `1.9.0`. VS Code `1.1.1` and MCP `1.0.1` are also separate unpublished candidates. Do not use this page as evidence that any registry, Action tag, Marketplace listing, or GitHub Release has been updated.
<!-- release-candidate-only:end -->

## Highlights

- Adds `adr-guard doctor [repository]`, a read-only local diagnostic command for CLI identity, repository detection, strict configuration, the effective ADR directory, .NET runtime, and optional Git availability.
- Adds GitHub Action support for explicit, read-only `drift` verification with rules, advisory/enforce policy, optional existing baseline, and bounded external evidence.
- Improves contributor onboarding and developer diagnostics while preserving deterministic validation and human ownership of ADR status and approval.
- Includes the Phase 1/2 maintainability and security work, the cognitive-complexity reductions completed in PR #300, and expanded reliability/regression coverage.

## Compatibility

- `doctor` is additive. Existing commands, arguments, defaults, exit codes `0`–`4`, JSON schema `1.0`, SARIF `2.1.0`, fingerprints, and deterministic ordering remain compatible.
- Action `drift` delegates policy and findings to the CLI container. The adapter validates paths and inputs and renders a bounded summary; it does not implement a second drift rule engine.
- The CLI still references internal, non-packable `AdrGuard.Core`. MCP references the same Core project directly and remains independent from the CLI executable.
- The independently installed VS Code extension invokes the CLI externally. VS Code `1.1.1` and MCP `1.0.1` remain separately versioned and are not bundled with this package.
- The runtime remains .NET 10. Git is optional except for commands that explicitly require local Git evidence; configured AI providers remain opt-in for `draft` and `review`.

## Distribution prepared by this release

After merge and a successful CI run for the selected `main` commit, an authorized maintainer may manually dispatch **Release** with `version=1.10.0`. The workflow validates, builds, tests, packs, and smoke-tests the release build before it can:

- publish `RodriOliveira.AdrGuard` `1.10.0` to NuGet.org and GitHub Packages;
- publish the same CLI build for `linux/amd64` and `linux/arm64` to GHCR and Docker Hub;
- create or verify the exact `v1.10.0` tag, move the `v1` compatibility tag only after publication gates pass, and create the matching GitHub Release;
- expose Action `drift` through the exact and moving Action tags with its runtime image resolved to `1.10.0`.

No publication, tag creation, or tag movement occurs merely by merging this preparation.

## Security and reliability

- Container build/runtime bases use official .NET Alpine images, retain bounded Git support, and run as a non-root user.
- Release publication retains pinned actions, least-privilege job permissions, CI/provenance checks, package installation smoke tests, vulnerability scanning, multi-platform manifest verification, SBOM, and provenance attestations.
- Missing, malformed, unsupported, or out-of-scope drift evidence remains `unknown`/inconclusive rather than inferred compliance.

## Related independent components

- MCP `1.0.1`: seven read-only schema `1.0` tools over `stdio`, direct Core reference, no CLI executable dependency. The checked-in `.mcp/server.json` intentionally remains at the published `1.0.0`; **MCP Release** generates the requested manifest during its run.
- VS Code `1.1.1`: maintenance patch for VS Code `1.101.0+`; the VSIX includes neither CLI nor MCP. The repository workflow only produces a validated artifact, and Marketplace publication remains a separate manual owner action.
